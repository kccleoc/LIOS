# RFC-002: LIOS v3.0 — Open-Source Bifurcation

## Summary
Bifurcate the LIOS repository into a public framework-only repo and a private personal-data repo. Extract Leo-specific Locked Decision content (L2/L3 tickers+caps, L7 permanently-exited list) to personal `state.yaml` parameters, preserving the form of all Locked Decisions as framework invariants.

## Motivation
LIOS v2.1 houses 84 framework files and 79 personal-artifact files in a single private repository. The repository is being opened to the public under the LIOS name. Leo's actual portfolio holdings, dollar amounts, historical snapshots, research notes, and market data are interleaved with the framework across both file trees and git history. Opening the repo requires extracting all personal data without damaging the framework's conceptual integrity.

## Proposed Change

### Three-repo topology
1. **kccleoc/LIOS** (public) — framework only; synthetic examples; history from v2.0.0 boundary
2. **kccleoc/LIOS-mine** (private) — Leo's live data + vendored framework copy pinned at a tag
3. **kccleoc/LIOS-archive** (private, frozen) — original contaminated repo, renamed; old URL redirects

### Locked Decision reframes
- L2 form: "Sleeve A has permanent target allocation; ETFs/weights live in `state.yaml: sleeve_a.allocation`"
- L3 form: "Sleeve B per-position NLV caps are binding; ticker+cap values live in `state.yaml: sleeve_b_caps`"
- L7: removed from public framework (Leo-specific exited-name discipline, not a framework invariant); L-number stub preserved per no-renumber rule; concept moved to `state.yaml: sleeve_a.permanently_exited`

### Parameter extraction (10b full sweep)
- Every ticker/dollar reference in framework dirs → extracted to state.yaml or generalized to synthetics
- Sleeve C/D target percentages → state params (P2)
- Monthly DCA amount → `state.yaml: monthly_dca`
- Sleeve D holding stages → `stage:` field per position
- All command-file example outputs replaced with synthetic EXAMPLE-* tickers

### Cloner onboarding
- `examples/state.schema.yaml` — empty contract with # TODO placeholders (machine-checkable CI target)
- `examples/state.example.yaml` — fully synthetic populated demo ($1M NLV, EXAMPLE-A/B/D tickers)
- `examples/snapshots/2026-01-01_portfolio.md` — generated synthetic snapshot demonstrating output format

### Vendored-pin consumption model
- Private repo vendors framework/ at a named git tag
- `framework/VERSION` records the pinned tag
- `bin/pull-framework.sh` updates non-flagged files, preserves PRIVATE-FORK-flagged files, exits nonzero if any preserved (13b)

## Impact
- Constitution: L2/L3 reframed (form preserved); L7 removed (stub retained); all other L1-L18 untouched
- Core: sleeve target references → state refs; worked examples → synthetic
- Commands: all 26 command file example outputs → synthetic; ticker leaks scrubbed
- Portfolio: state.yaml extended with new parameter fields (sleeve_a, sleeve_b_caps, sleeve_c, sleeve_d, monthly_dca)
- New: examples/ dir, RFC-002, ADR-003, updated glossary, rewritten README, CHANGELOG v3.0

## Alternatives Considered
1. **Submodule consumption** — rejected: tooling friction with opencode/codegraph/LSP on submodule traversal; vendored copy is simpler and reversible
2. **Subtree consumption** — rejected: prose merge conflicts when framework edits diverge; vendored pin is postponable — can convert to subtree later if behavior proves canonical
3. **Single-repo .gitignore-only** — rejected: history is already contaminated (commit messages, snapshots in git history); .gitignore protects future only, not past
4. **L3-only reframe** — rejected per P1: L2 and L7 are also entangled; all three must be extracted for the framework to be ticker-neutral
