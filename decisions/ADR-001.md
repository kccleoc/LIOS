# ADR-001: LIOS v2.0 Modular Architecture

## Context
LIOS v1.5 was organized as a flat prompt-driven framework: paste lios/v1.5.md into an AI session → AI holds framework in memory → user pastes commands. This model has limitations:
- AI memory is opaque and non-versioned
- Framework rules live only in paste-ready prompts
- No separation between constitutional, operational, and research knowledge
- Difficult for autonomous agents to navigate and maintain

## Decision
Reorganize LIOS into a modular, agent-native architecture with distinct knowledge layers:

- **constitution/** — Permanent knowledge: locked decisions, mission, principles, governance
- **core/** — Framework implementation: kelly, sleeves, SR, replacement index, research layer, health check, execution engine, investment committee
- **portfolio/** — Operational knowledge: current holdings, snapshots, transactions, performance
- **research/** — Research knowledge: company analysis, economic engines
- **scores/** — Quick-reference score cards
- **playbooks/** — Agent workflow definitions
- **workspace/** — AI operating desk (temporary, continuously updated)
- **templates/** — Reusable document templates
- **rfcs/** — Proposed changes
- **decisions/** — Architecture Decision Records
- **archive/** — Historical version snapshots

## Consequences
### Positive
- Agents can navigate the framework by reading individual files
- Clear separation of permanent, operational, and research knowledge
- Version-controlled source of truth independent of AI memory
- RFC/ADR workflow for future changes
- Maintains backward compatibility via preserved paste-ready prompts

### Negative
- Dual paths during transition (paste-ready + agent-native)
- More files to maintain (~50+ new files)
- AGENTS.md and README.md need updating

## Alternatives Considered
1. Incremental refactor within existing lios/components/ structure — rejected: does not achieve the three-class knowledge separation
2. Monorepo with submodules — rejected: over-engineered for a documentation-only repo
3. Stay on v1.5 flat structure — rejected: prompt-driven model limits agent autonomy and maintainability
