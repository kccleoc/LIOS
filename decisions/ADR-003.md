# ADR-003: LIOS v3.0 — Open-Source Bifurcation

## Context
LIOS v2.1 established `portfolio/state/portfolio.yaml` as the SSOT and demoted `current/`, `snapshots/`, and `reports/` to generated views (ADR-002). The repo had grown to 84 framework files plus 79 personal-artifact files, with the two categories entangled inside the constitutional files themselves — Locked Decisions L2, L3 and L7 each named specific instruments and specific weights, so a constitutional rule and one investor's parameter values were the same sentence. That conflates the *form* of each Locked Decision with the *values* it happens to hold. The repo is private; opening it to the public requires extracting the personal data without destroying the framework's conceptual integrity. The specific tickers, weights and caps are recorded only in the private `state.yaml`.

## Decision
LIOS v3.0 bifurcates the project into three repositories and reframes the three entangled Locked Decisions.

### Three commitments

**A. Repo bifurcation.** Three repos:
1. **kccleoc/LIOS** (public, clean) — framework only; synthetic examples under `examples/`; git history carried from the v2.0.0 boundary (`f5fff95`), with personal-data paths and commit-message leaks filtered out via `git filter-repo`. All Locked Decision forms preserved; L7 removed (Leo-specific, not a framework invariant); L-number stub retained per AGENTS.md's no-renumber rule.
2. **kccleoc/LIOS-mine** (private) — Leo's live working repo: `portfolio/state/portfolio.yaml` (SSOT), `portfolio/snapshots/`, `research/`, `reports/`, plus a *vendored pinned* copy of the public framework under `framework/` with `framework/VERSION` recording the pinned tag.
3. **kccleoc/LIOS-archive** (private, frozen) — the original contaminated `kccleoc/LIOS` repo, renamed via GitHub UI. Never modified; preserved as Leo's personal provenance. Old URL redirects silently.

**B. Vendored-pin consumption.** The private repo consumes the public framework as a vendored copy (not submodule, not subtree). Reasons:
- Submodule: tooling friction with opencode, codegraph, and LSP indexing on submodule traversal — Leo's day-to-day ops would pay that friction on every session
- Subtree: prose merge conflicts when framework files diverge from private-fork edits are worse than on code; the repo is doc-heavy
- Vendored-pin: simplest, fastest, reversible to subtree later if Leo's behavior proves consistently canonical
- `bin/pull-framework.sh <tag>` handles updates (13b behavior: non-flagged files update, `<!-- PRIVATE-FORK -->` flagged files preserved, exit nonzero if any preserved)

**C. L2+L3+L7 form-vs-parameters refactor + L7 removal from public framework.** Three Locked Decisions rephrased to separate their *form* (framework invariant) from their *parameter values* (personal, now in `state.yaml`):
- L2 form: "Sleeve A has a permanent target allocation composed of broad-index ETFs held at fixed within-Sleeve weights summing to 100%"; instrument tickers and weights → private `state.yaml`
- L3 form: "Sleeve B per-position NLV caps are binding (buying pause + trim)"; instrument tickers and cap percentages → private `state.yaml`
- L7: removed from public framework (a specific permanently-exited list is a portfolio-local discipline, not a framework invariant); L-number stub retained per no-renumber rule; the concept of a portfolio-local permanently-exited list lives in the private `state.yaml`
- Extended extraction (P2): the sleeve target percentages and the monthly contribution amount → private `state.yaml` parameters
- These reframes ride as *minor changes contingent on* the v3.0 major-version OSS-split event. Future *standalone* L2/L3/L7 content amendments still require v3.0+ major bumps, preserving AGENTS.md's "Locked Decision changes require a major version bump" rule.

## Consequences

### Positive
- **Privacy guarantee:** the public repo contains zero real ticker symbols, zero real dollar amounts, and zero portfolio holdings — enforced by the leak-prevention check in the private `bin/push-framework.sh`, which holds the instrument list outside the public tree
- **Framework integrity:** all Locked Decision forms preserved; L1-L18 structure intact (L7 gapped per no-renumber rule, not renumbered)
- **Cloner onboarding:** `examples/state.schema.yaml` is the machine-checkable contract; `examples/state.example.yaml` provides a fully runnable synthetic demo
- **Leo's provenance preserved:** `kccleoc/LIOS-archive` keeps the full historical record untouched — v1.x prompts, portfolio snapshots from v1.3 to v2.1.2, all research — never edited, never deleted
- **Reversible consumption:** vendored-pin can be converted to subtree later without data loss

### Negative
- **Three repos to manage:** Leo must push framework changes to public `kccleoc/LIOS`, tag them, then pull via `bin/pull-framework.sh` into the private repo — a two-hop flow
- **State.yaml migration:** Leo's `portfolio/state/portfolio.yaml` must be extended with new parameter fields (sleeve_a, sleeve_b_caps, sleeve_c, sleeve_d, monthly_dca, stage per D position). Existing snapshots and generated reports from before the split may differ structurally from post-split generator output; a one-time reconciliation pass required
- **`git filter-repo` historical commit-message scrub is imperfect:** regex on commit messages can over-redact or under-redact; post-push grep on `git log` is the real safety net; any leaked tickers require manual per-message rewrite
- **Private-fork collisions:** if Leo edits a framework file inside the private repo (flagged `<!-- PRIVATE-FORK -->`), the next `pull-framework.sh` aborts on that file until reconciled — intentional friction to discourage silent divergence

## Alternatives Considered
1. **Single-repo .gitignore-only approach** — rejected: git history already contains portfolio data in commit messages and snapshots; a .gitignore protects the *future* working tree but not the *past* commit graph; `git clone kccleoc/LIOS && git log -p` would reveal every historical snapshot
2. **Submodule consumption** — rejected: submodules are a known friction point for the tools Leo uses daily (opencode, codegraph, LSP); the repo is documentation-heavy; the cost is recurring, not one-time
3. **Subtree consumption** — rejected: prose merge conflicts on doc-heavy repo when framework and private-fork edits diverge; vendored-pin is the reversible deferral — convert to subtree later if behavior proves canonical
4. **L3-only reframe, leave L2 and L7 as-is** — rejected per P1 decision: L2 and L7 are also Leo-specific and would leak into the public framework; all three must be reframed for ticker-neutrality
5. **Keep L7 as a framework-invariant "permanently-exited list" concept** — rejected per P3: the "permanently-exited" discipline is portfolio-local — every cloner's list is different; the constitutional weight of an L-number is unnecessary for a concept whose content varies per user

---

*ADR-001 (v2.0 modular architecture) and ADR-002 (v2.1 SSOT architecture) remain accepted. ADR-003 records the v3.0 bifurcation — the structural consequence of opening LIOS to the public.*
