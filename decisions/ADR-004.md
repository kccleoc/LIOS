# ADR-004: LIOS v3.0.1 — Flow-UP Infrastructure

## Context

ADR-003 established the vendored-pin model: the public framework repo (`kccleoc/LIOS`) is consumed as a vendored copy under `framework/` in the private data repo (`kccleoc/LIOS-mine`), pinned at a specific tag recorded in `framework/VERSION`. Flow DOWN (public → private) is handled by `bin/pull-framework.sh <tag>`, which clones the public repo at a tag into a tempdir, diffs the clone against the local `framework/`, and updates non-flagged files while preserving files containing `<!-- PRIVATE-FORK -->` markers.

ADR-003 §B-negative documented a gap: Flow UP (private → public) was left unscripted. Leo must push framework changes to the public repo, tag them, then pull back via `bin/pull-framework.sh` — a "two-hop" flow with no automation for the first hop. This ADR closes that gap.

## Decision

A symmetric `bin/push-framework.sh <new-tag> [<commit-msg-file>] [--dry-run]` script is added to the private repo, mirroring the design of `bin/pull-framework.sh`.

### Design

1. **Clone-in-tempdir.** Push-framework.sh clones `kccleoc/LIOS` at the pinned tag (read from `framework/VERSION`) depth-1 into a tempdir. It does NOT operate on the LIOS-mine working tree's own git history. Rationale: same vendored-pin philosophy as pull — avoids nested-git tooling friction (ADR-003 §B's submodule rejection applies equally to nested plain git repos); symmetric with pull; the agent-DOES-it-for-me UX is identical to the nested-repo option without its downsides.

2. **PRIVATE-FORK inversion rule.** Files in `framework/` containing `<!-- PRIVATE-FORK -->` markers are SKIPPED during push. They never go upstream. This is the mirror-reverse of pull-framework.sh's preserve logic (pull keeps flagged files; push skips them). The marker convention is identical across both scripts.

3. **Tag safety.** The script refuses to push if `<new-tag>` already exists on `kccleoc/LIOS` origin (checked via `git ls-remote --tags`). Tags are immutable; overwriting is not permitted.

4. **Dirty-tree refusal.** The script refuses to run if `framework/` has uncommitted changes in LIOS-mine (both unstaged and staged-but-uncommitted). The vendored copy must be clean before pushing.

5. **No-change detection.** If no non-FORK changes are detected, the script exits 0 with "nothing to push." If only FORK files would change, it exits 1 (same semantics as pull's exit 1 for preserved files).

6. **Leak-prevention gate.** Before commit, the script runs the same ticker and dollar-amount greps from `framework/AGENTS.md` on the tempdir clone. Any match aborts the push. This is the privacy firewall — real portfolio data must never reach the public repo.

7. **Commit-message handling.** An optional second argument accepts a commit message file path. If omitted, `git commit -e` opens the editor for the user to compose the message interactively.

8. **Post-push auto-re-pin.** After a successful push+tag, the script auto-runs `bin/pull-framework.sh <new-tag>` to re-pin the vendored copy and sync. This restores bidirectional symmetry in a single command.

9. **Dry-run mode.** `--dry-run` performs all steps except the actual push, prints the planned actions, and exits 0. This is the primary verification mechanism — the agent runs dry-run first to confirm correctness, then the user runs the real push.

10. **No-auto-push discipline.** The script always requires explicit user invocation. It never auto-commits or auto-pushes from any automated workflow. Per AGENTS.md's no-auto-commit rule, `git commit` and `git push` to the public repo are user-initiated actions.

### Exit codes

| Code | Meaning |
|---|---|
| 0 | Success (pushed and re-pinned), or nothing to push |
| 1 | One or more PRIVATE-FORK files skipped (no non-FORK changes pushed) |
| 2 | Failure (clone error, push rejection, leak detected, dirty tree, tag exists) |

### Script location

`bin/push-framework.sh` lives in the private repo (`kccleoc/LIOS-mine`), NOT in the vendored `framework/` copy. It is a private repo tool, like `bin/pull-framework.sh`. The script's evolution is separate from the framework version it manages.

## Consequences

### Positive

- **Symmetric bi-directional Flow-UP/DOWN.** Two scripts, identical design philosophy, complementary logic. Pull-framework.sh brings public changes down; push-framework.sh sends private edits up.
- **Privacy-guaranteed.** PRIVATE-FORK inversion + leak-prevention greps form a dual firewall. The public repo cannot receive ticker- or dollar-amount-contaminated content through the vendored-pin channel.
- **Reproducible.** `framework/VERSION` continues to pin an exact public tag. Every LIOS-mine commit carries a deterministic framework snapshot.
- **Reversible.** ADR-003's subtree-later promise extends to this design — converting from vendored-pin (with two scripts) to git subtree is lossless. Both scripts operate on tempdir clones, not on LIOS-mine's git history.
- **Verifiable.** `--dry-run` mode lets the agent or user preview every push before it executes.

### Negative

- **Two hops remain.** Edits happen in the vendored copy, push goes through the script, pull re-pins. This is structural per ADR-003, not a script defect. Removing a hop would require either a nested git repo (rejected — contradicts ADR-003's submodule rejection) or subtree conversion (deferred per ADR-003).
- **Script is private-only.** `bin/push-framework.sh` lives in the private repo and is NOT itself pushed to the public framework. Its evolution is separate from the framework version it manages. A collaborator using the public `kccleoc/LIOS` clone-and-edit workflow would not use this script — it is Leo's personal tool.

## Alternatives Considered

1. **Nested git repo inside `framework/`, gitignored at the parent layer** — rejected. A nested plain git repo (not a submodule) is mechanically workable but (a) contradicts ADR-003's submodule rejection — the same tooling friction (opencode/codegraph/LSP at the nested `.git` boundary) applies equally; (b) loses the vendored-pin reproducibility property — `framework/VERSION` pinning is replaced by a live HEAD pointer, and `git clean` of the parent drops `framework/` entirely (it's gitignored); (c) breaks the `<!-- PRIVATE-FORK -->` workflow — every local commit in the nested repo becomes a divergent-branch commit that must be kept off upstream; (d) the "agent does it for me" UX is fully achievable via the script approach without these trade-offs.

2. **Manual second-folder workflow** — rejected. Requires cloning `kccleoc/LIOS` to a separate directory on disk, editing there, pushing, then running `bin/pull-framework.sh` in LIOS-mine. Leo explicitly wants to avoid opening a second VSCode folder for framework maintenance.

3. **Git subtree** — deferred to a later decision (per ADR-003 §B). Subtree is a strictly more complex initial setup (squash-merging prose conflicts on a doc-heavy repo). Vendored-pin with two scripts is the simpler starting point; subtree conversion is always available later.
