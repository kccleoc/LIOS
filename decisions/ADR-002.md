# ADR-002: LIOS v2.1 Single Source of Truth Architecture

## Context

LIOS v2.0 organized the framework into modular directories but did not enforce
data consistency. Portfolio numbers were duplicated across multiple files:
`snapshots/*.md`, `portfolio/current/portfolio.md`, `portfolio/current/allocation.md`,
`portfolio/current/cash.md`, and `workspace/today.md`. When the snapshot was updated,
these files diverged — the NLV in `portfolio/current/portfolio.md` ($199,412.71)
disagreed with the latest snapshot ($203,813.11) by $4,400.40. Cash breakdowns
were inconsistent ($0 SR vs $3,500 SR).

This state drift made reports unreliable and forced agents to guess which file
held the authoritative data. The system needed a single source of truth.

## Decision

Adopt a Single Source of Truth (SSOT) architecture:

1. **Canonical state file:** `portfolio/state/portfolio.yaml` is the ONE file
   containing all live portfolio data — positions, cash, NLV, computed totals.
   
2. **Generated documents:** All other files containing portfolio numbers
   (`portfolio/current/*.md`, `portfolio/snapshots/*.md`, `workspace/*.md`,
   `reports/*.md`) are derived from the state file. They carry a "GENERATED"
   banner and are never manually edited.

3. **Reconciliation engine:** Before any report is written, the system computes
   Σ(position market values) + cash.balance and compares against NLV. Tolerance
   is ±$1.00. If exceeded, generation aborts with a reconciliation failure report.

4. **Validation pipeline:** 9 automated checks run before any generation. Any
   failure aborts the pipeline. Results are logged to `logs/validation/`.

5. **Event pipeline:** A documented 15-step workflow from IBKR update through
   GitHub push ensures deterministic, reproducible state transitions.

## Consequences

### Positive
- **Deterministic:** Every report is reproducible from the same state file
- **Self-healing:** State drift is detected at generation time, not discovered later
- **Auditable:** Validation logs provide a complete audit trail
- **Agent-native:** Agents know exactly which file to read and which to generate
- **Backward compatible:** All existing files preserved; no investment rules changed

### Negative
- **More files:** ~40 new files across state, reports, validation, execution, market
- **Discipline required:** Agents must follow the generation pipeline; bypassing it
  reintroduces state drift
- **Learning curve:** New agents must understand the SSOT architecture before operating

## Alternatives Considered

1. **Keep v2.0 flat structure, improve documentation** — rejected: does not solve
   the state drift problem; documentation cannot enforce consistency.
2. **Database-backed state (SQLite)** — rejected: over-engineered for a 
   documentation-only repo; YAML is human-readable and version-controls cleanly.
3. **JSON state file** — rejected in favor of YAML: YAML is more human-readable 
   and better suited to a documentation-only repo where humans and AI both read it.

---

*ADR-001 remains accepted (v2.0 modular architecture). ADR-002 supersedes the
v2.0 flat-document approach with SSOT enforcement.*

## Amendment — 2026-07-29 (v2.1.2)

**Operational NLV is computed, not IBKR-reported.**

IBKR Account Summary NLV can lag position marks (API/session timing). LIOS
therefore sets:

- `nlv` = `Σ(position.market_value) + cash.balance` — **authoritative** for all
  reports, caps, drift, and Kelly dollar math
- `ibkr_nlv` = IBKR Reported NLV — **reference only**
- Check 9 fails only when `|nlv − portfolio_total| > $1.00`
- `|ibkr_nlv − nlv|` is logged as INFO and never aborts generation

This amendment does not change Locked Decisions L1–L18.
